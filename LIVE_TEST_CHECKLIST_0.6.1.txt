DDS Companion 0.6.1 — Windows Live Gate
========================================

Prerequisite:
- resolve whether «только кэш / только текст / как выбрано в Библиотеке» belongs to import or future export.
- preserve a backup of the current real DDS data before deliberately testing full archive reset.

0. BUILD / IDENTITY
[ ] Run build_windows.bat successfully.
[ ] dist\DDS\DDS.exe exists and starts directly.
[ ] Explorer/taskbar/Alt+Tab use the approved DDS icon.
[ ] File Properties reports DDS — Discord Data Snatcher, version 0.6.1.
[ ] Main title is shown once; no duplicated «DDS — Discord Data Snatcher» suffix.
[ ] Sidebar branding shows DDS / Discord Data Snatcher without a competing «Companion» subtitle.

1. EXISTING ARCHIVE REGRESSION
[ ] Normal DDS.exe resolves DataRoot to %LOCALAPPDATA%\DDS_Companion.
[ ] Existing settings and SQLite archive open in place.
[ ] Library servers/channels/threads/messages are intact.
[ ] Existing cached images still render.
[ ] Watcher, Activity, Status and Diagnostics are responsive.

2. CACHE CLEAR — NON-DESTRUCTIVE
[ ] Clear media cache.
[ ] Messages/links/Library remain in SQLite.
[ ] Media files are removed.
[ ] Session storage text says «Освобождено за сессию: …», not a raw negative number.

3. EXPIRED MEDIA URL FLOW
[ ] Encounter/reproduce an expired Discord media URL (401/403/404).
[ ] It does NOT appear as a routine «Ignore all» decision.
[ ] It becomes «ждёт переобнаружения» / UNRESOLVED.
[ ] Diagnostics report contains technical rediscovery details.
[ ] Revisit/scroll the original Discord message so Plugin observes a fresh URL.
[ ] Same attachment becomes KNOWN and then CACHED automatically.
[ ] A simulated/real transient network failure remains retryable rather than rediscovery-only.

4. FULL LOCAL ARCHIVE RESET — DESTRUCTIVE TEST
[ ] Click «Сбросить локальный архив» and verify explicit irreversible-warning dialog.
[ ] Cancel once; verify nothing is deleted.
[ ] After backup, confirm reset deliberately.
[ ] SQLite archive + WAL/SHM + media cache are removed/recreated as appropriate.
[ ] settings.json and user settings survive.
[ ] UI returns with zero/new-history archive state and stays responsive.
[ ] Existing untouched DDS_Data captures do NOT immediately repopulate the old archive.
[ ] Revisit one Discord source so Plugin rewrites a capture after reset.
[ ] Only the refreshed capture becomes eligible and imports into the new archive.

5. SHUTDOWN / RESTART
[ ] Normal close exits cleanly with no traceback/hung worker.
[ ] Restart preserves the new clean archive state and reset boundary.

LOCAL ACCEPTANCE GATE
Only after applicable checks PASS may 0.6.1 be frozen as the validated local baseline.
Do NOT publish to GitHub automatically; repository/release work remains paused until explicitly reopened.
