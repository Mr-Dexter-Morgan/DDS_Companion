DDS Companion 0.5.6 — Live UX cleanup / Library media state / Activity dedup

- Библиотека: в каждой ветке теперь показано не только историческое число вложений, но и текущий жизненный цикл медиа: известно/всего, кэшировано, требует внимания, обработано, ждёт переобнаружения.
- Библиотека: правый заголовок выбранного канала/темы показывает те же branch-level media counters.
- Библиотека: Discord Markdown в сообщениях отображается как форматированный текст вместо сырых `*` / `**` / `~~` / backticks.
- Библиотека: исправлена высота комбобоксов «Выгрузка» и строк дерева; колонка больше не должна резать текст по вертикали.
- Библиотека: при фоновой перестройке дерева сохраняется позиция прокрутки.
- Жизненный цикл медиа: список «Медиафайлы, требующие внимания» больше не перестраивается на каждом snapshot, если сами строки не изменились.
- Жизненный цикл медиа: при реальном изменении списка сохраняются выбранная строка и вертикальная позиция прокрутки; live bug «доскроллил вниз → refresh бросил наверх» закрыт по коду.
- Жизненный цикл медиа: RUNNING остаётся системным здоровьем, но рядом явно показывается количество объектов, ожидающих переобнаружения.
- Активность: пользовательский журнал русифицирован; subsystem/event ID теперь представлены человеческими названиями, технический event ID оставлен в tooltip.
- Активность: старый heartbeat-spam одинаковых `health_reason_changed` схлопывается при отображении.
- Health transition dedup: подпись причины теперь строится по стабильным `subsystem + reason code + subsystem state`, а не по динамической строке с возрастом heartbeat. Изменение `24433 s -> 24435 s` больше не создаёт новое событие.
- Статус: основные карточки и временные подписи дополнительно русифицированы.
- Topbar/Dashboard: пользовательская последняя активность проходит через тот же human-readable formatter.
- Логика Ignore All -> Clear Processed -> UNRESOLVED -> fresh rediscovery не менялась; live-проверка 0.5.5 подтвердила, что этот сценарий работает ожидаемо.
