DDS Companion 0.4.5 — Startup Foreground Candidate
=================================================

Status: BUILT / LOCAL TESTING

Purpose
-------
Fix the Windows launch UX found at the end of the 0.4.4 live test: when
Companion is started from Explorer, Explorer can remain in front while the
Companion window opens behind it.

Changed
-------
- Added a one-shot startup foreground request after the native Qt window exists.
- Qt raise/activate is attempted first.
- On Windows, a best-effort Win32 fallback briefly toggles TOPMOST and
  immediately removes it before requesting foreground.
- The startup foreground path is guarded so later show/unminimize events cannot
  steal focus.
- Foreground polish failures are isolated and cannot prevent Companion startup.
- Health now treats a fresh/stale plugin heartbeat as NOT RUNNING whenever the Discord process is definitely not running; last heartbeat metadata is retained for diagnostics.

Unchanged
---------
- Health semantics and plugin-heartbeat-v1 integration from 0.4.4.
- Archive schema and accumulated data.
- Import/dedup/watcher capture semantics.
- Dashboard, Library, Activity, Health and Settings information architecture.
- No media downloading, AI export, updater backend or cloud synchronization.

Validation
----------
- Python compileall: PASS.
- Full automated suite: 40/40 PASS.
- Native Windows Explorer-launch validation: required.
