DDS Companion 0.6.0 — Application Foundation / Native Windows EXE candidate
=========================================================================

Status: FOUNDATION SOURCE READY / WINDOWS EXE BUILD + LIVE GATE PENDING
Base: DDS Companion 0.5.8 VERIFIED / LIVE TESTED / FULLY WORKING PROTOTYPE

Branding / Windows identity
---------------------------
- Approved DDS hooded-snatcher artwork is now the canonical application icon.
- Added packaged assets/DDS.ico and DDS_app_icon_master.png.
- Product identity fixed as: DDS — Discord Data Snatcher.
- Windows executable name fixed as: DDS.exe.
- Stable AppUserModelID: DDS.DiscordDataSnatcher.Companion.
- GUI loads the approved asset instead of generating the old DDS text icon at runtime.
- Sidebar branding now uses the approved artwork.
- Diagnostics now includes a product identity/logo card.

Application foundation / DataRoot
---------------------------------
- Added one deployment-neutral DataRoot/path-provider boundary.
- Installed profile preserves the existing data root exactly:
  %LOCALAPPDATA%\DDS_Companion
- Portable profile resolves durable data relative to the application directory:
  <DDS app dir>\Data\...
- Explicit --app-data remains a development/diagnostic override.
- All logical config/database/media/cache/logs/backups paths derive from the same resolved root.
- Runtime snapshots/diagnostics expose deployment profile and application directory.
- Added --portable to GUI and CLI launch paths.

Native EXE build contract
-------------------------
- Added DDS.spec for an inspectable PyInstaller onedir build.
- Added Windows version resource with ProductName/FileDescription/FileVersion/ProductVersion.
- Added build_windows.bat and isolated build requirements.
- EXE build includes the approved DDS.ico and packaged UI master artwork.
- BAT/pythonw remains only as source/development compatibility while the packaged product path moves to DDS.exe.
