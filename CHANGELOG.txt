Unreleased - DDS Companion 0.7.0 Safe Updater Foundation (release-ready freeze)

Status
- Source/product version is frozen at 0.7.0.
- Public baseline remains v0.6.2 until v0.7.0 is explicitly published.
- Final local Windows release gate is complete; the GitHub v0.7.0 tag/release has not been created yet.

Safe update architecture
- DDSUpdater.exe is a separate external updater; the running DDS payload never overwrites itself.
- DDS.exe is a stable bootstrap; application payloads live under versions/<version>.
- current.json selects the active version, previous.json records the previous successfully-started version, and pending_update.json makes promotion transactional.
- Candidate promotion is committed only after startup acknowledgement; failed startup automatically rolls back.
- Startup acknowledgement is tied to core runtime readiness, not completion time of the initial full archive import.
- Startup commit is idempotent and repairs the power-loss window between durable pending state and current-pointer switch.
- Launcher startup removes only orphan/unreferenced version directories; authoritative current/previous/pending versions are preserved.

Integrity and isolation
- Release manifest includes channel, asset, SHA-256, exact size, updater protocol and package format.
- Downloads use atomic partial promotion only after exact size and SHA-256 verification.
- ZIP validation rejects traversal, drive paths, symlinks, Windows case collisions and protected user-data roots.
- Staging verifies the package and DDS.install.json before promotion.
- SQLite/archive, settings, media/cache, exports and DDS_Data are outside updater ownership.
- Regression tests prove user-data sentinels remain byte-identical after success and forced rollback.

Recovery and observability
- OS-backed cross-process update.lock prevents concurrent update ownership.
- Free-space guards run before download/staging and before install.
- updater.log records promotion, startup confirmation and rollback.
- journal.json records durable updater lifecycle states.
- Failed Windows candidates are terminated as a process tree and removed with bounded retry.
- Rollback preserves the already-committed previous working build and relaunches the restored version.
- Release/download operations use bounded timeout/retry and cancellation cleanup.
- Background update attempts are throttled to at most once per 24 hours even when GitHub is unavailable.

Update UX
- Settings provides manual check/download/install flow.
- Background checking, automatic download and automatic install are independently controlled; auto-install implies auto-download.
- Automatic install never closes DDS merely because a package finished downloading; a staged package installs at natural exit unless the user selects Install now.
- Release notes are normalized and bounded before display.
- Window/presentation state is captured for update restart; tray-hidden restoration is architecture-ready for the 0.8.0 tray layer.
- Update/network failure never blocks archive use.

Build/release hardening
- Windows FileVersion/ProductVersion metadata is generated from dds_companion.__version__ on every build.
- build_windows.bat fails closed if old build/dist trees cannot be cleaned after bounded retry; silent partial rmdir cleanup is no longer possible.
- A Windows named mutex protects the whole build pipeline; a concurrent build exits 16 before touching shared build/dist trees.
- ZIP creation retries bounded transient Windows file-read races and then validates the completed archive with testzip.
- Final DDS.exe, DDSUpdater.exe and DDSApp.exe report FileVersion/ProductVersion 0.7.0.
