DDS Companion 0.6.2 — Unified Manual Export / Branch Management / Branding

Base
- Starts from accepted Windows-live-tested DDS Companion 0.6.1 candidate-r1.
- Keeps 0.6.1 archive reset boundary, passive expired-media rediscovery and storage wording behavior.

Branding
- Window title: DDS — Discord Data Snatcher.
- Removed version and duplicate DDS suffix from normal title chrome.
- Sidebar brand: larger/stronger centered DDS; Discord / Data / Snatcher below on separate lines.
- Version remains available in Diagnostics.

Unified manual export
- Added provider-independent ExportPackageService.
- Library context menu: Упаковать -> Только текст / Текст + кэш.
- Canonical output format: ZIP.
- Package contract:
  manifest.json
  content.md
  messages.json
  media_index.json
  media/ (Text + Cache only)
- Package media filenames use stable SHA-256-derived collision-safe prefixes.
- Missing/not-cached/awaiting-rediscovery media remains visible in manifest/index.
- Text-only export contains no media bytes.
- Manual export never changes persistent Library export rules.
- Added persistent manual_export_path setting and folder picker.
- Packaging uses staging, validates the ZIP by reopening/testzip/manifest read, then atomically promotes the final file.
- Failure cleanup prevents false-success ZIP artifacts.
- Activity gets human-readable manual-export events.

Branch management
- Added branch-scoped media cache clear.
- Added branch data deletion while preserving structural node and export rule.
- Added full branch deletion including descendants and export rules.
- Destructive branch maintenance stops archive/media runtime before mutation and restarts DDS afterwards.
- Historical capture_imports are intentionally preserved as a dedup boundary so untouched old DDS_Data does not immediately repopulate a deliberately deleted branch; a genuinely updated capture can reappear later.
- Orphan media registry rows/cache files are removed after data deletion; still-referenced media is preserved.
- Activity gets human-readable branch-maintenance events.

Cloud/sync decision
- Direct Google Drive OAuth/API integration is not part of DDS.
- Future automatic sync will write to a user-selected ordinary filesystem folder; external clients such as Google Drive for Desktop/OneDrive/Dropbox/Yandex Disk/etc. may sync it.
- 0.6.2 itself implements manual ZIP export only; background folder sync is a later layer.

Release direction
- If automated + real Windows live gates pass, 0.6.2 is the intended first public binary GitHub Release.
- Planned post-0.6.2 order: Updater -> Tray/Autostart -> Setup/Repair/Installer -> 1.0.

0.6.2 candidate-r2 — Windows Known Folder correction
- Fixed the default manual-export directory on Windows when the user's Documents folder has been moved or redirected to another drive.
- Replaced the naive Path.home()/Documents assumption with the Windows FOLDERID_Documents Known Folder lookup (SHGetKnownFolderPath), with a safe fallback.
- Portable export behavior remains Data/exports.
- Added regression coverage for redirected Windows Documents and the Portable default.
