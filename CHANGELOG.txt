DDS Companion
Version: 0.2.0
Date: 2026-09-13
Authors: Mr_Dexter_Morgan, Masya

Watcher Layer release.

Changes since 0.1.0:
- Added continuous DDS_Data monitoring after the initial full import.
- Default launch mode is now persistent watch mode; use --once or run_once.bat for the old one-shot behavior.
- Added watcher/capture_watcher.py and watcher/file_events.py.
- Uses a standard-library polling watcher: no new third-party runtime dependency.
- Added configurable polling interval (--poll-ms, default 750 ms).
- Added configurable file settle window (--settle-ms, default 500 ms).
- New/changed capture.json files are imported automatically after they remain stable for the settle window.
- Added short retry handling for transient read/JSON decode failures.
- A malformed/invalid capture is isolated and recorded without stopping the watcher.
- Failed jobs for a capture are automatically marked resolved after that same capture imports successfully later.
- Duplicate unresolved failure rows for the exact same error/target are suppressed.
- Deleting capture.json never deletes already archived SQLite messages.
- Added watcher state/heartbeat/last-event data in application_state.
- Added clean Ctrl+C shutdown and watcher counters.
- Added JSON Lines watcher events when --json is used in watch mode.
- Startup race protection: filesystem state is snapshotted before full import so changes that occur during startup are caught afterward.
- Console wording now calls already-known message upserts "existing refreshed" rather than implying every occurrence is a semantic edit.

Compatibility:
- DDS Capture Schema v2.
- DDS Plugin v0.5.2 stable milestone.
- Existing DDS Companion 0.1.0 SQLite database is reused in-place; no destructive reset is performed.
- No media downloading, Discord token access, hidden history fetching, network transport, or Drive sync.
