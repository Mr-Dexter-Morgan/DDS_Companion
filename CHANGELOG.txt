DDS Companion 0.4.4 — Health Truthfulness & Plugin Heartbeat Candidate
=======================================================================

Status: BUILT / LOCAL TESTING

Purpose
-------
Make Health describe the whole DDS capture chain truthfully after 0.4.3 live
Windows testing exposed states that could remain green while the plugin itself
was disabled.

Changed
-------
- Replaced user-facing DEGRADED with LIMITED; legacy DEGRADED database rows are
  normalized on read for backward compatibility.
- Split sidebar product brand into DDS / Companion / version lines.
- Added DDS Plugin Health card and plugin-heartbeat-v1 consumer.
- Plugin 0.5.2/no heartbeat is reported as UPDATE AVAILABLE, not as broken.
- Fresh plugin heartbeat -> RUNNING; clean STOPPED -> NOT RUNNING; expired
  heartbeat -> STALE/NOT RUNNING; invalid heartbeat -> LIMITED.
- Discord NOT RUNNING contributes to overall LIMITED capture state but remains
  non-error and archived data stays available.
- Missing DDS_Data makes Watcher display WAITING FOR SOURCE rather than a
  misleading RUNNING status.
- Importer timestamp label changed from Heartbeat to Last import.
- Overall and per-card status labels expose explanatory tooltips.
- Activity persists Health transitions, reason changes and recovery without
  periodic duplicate spam.
- Update check remains truthful telemetry only; no fabricated GitHub success.

Unchanged
---------
- Archive schema and accumulated data.
- Import/dedup/watcher capture semantics.
- Dashboard, Library and Activity information architecture.
- No media downloading, AI export or cloud synchronization.
- No automatic plugin updater yet.

Validation
----------
- Python compileall: PASS.
- Full automated suite: 38/38 PASS.
- 0.4.3 archive/import regressions retained.
